# 发薪（工资发放）

发薪不是一个独立事项，而是**社保、公积金、个税三条链的交汇点**。
发一笔工资会同时决定：社保缴费基数申报、公积金缴存额、个税扣缴申报的三张表填什么数。
所以本文只解决一件事：**一笔工资的数怎么定、什么时候打钱、以及这个数在三个平台分别填在哪。**

> 具体金额（工资额、基数、缴费额）一律不写进本文，去私有档案取。

## 0. 一人公司先决策：走工资，还是走分红

法定代表人从自己公司拿钱有两条完全不同的通道，**税务处理相反**，先定了再谈发薪：

| | 工资薪金 | 股息红利 |
|---|---|---|
| 个人税负 | 累计预扣法，可扣 5000/月 + 三险一金 + 专项附加 | **20% 比例税，无任何扣除** |
| 企业所得税 | **可税前扣除**（减少企业利润） | 不可扣除（税后利润分配） |
| 前置条件 | 必须有真实用工关系 + 参保 + **实际支付** | 需有可分配利润、股东会决议 |
| 频率 | 月 | 按需 |

⇒ 有真实用工关系时**优先走工资**：企业端能扣、个人端有 5000/月 免征额。
⚠️ 但工资必须**真的打钱**（见 §4）。只在账上计提不打款，两头都站不住：
企业所得税汇算时计提未发部分要**调增**，个税也不能按发薪申报。

## 1. 一笔工资的五个数

顺序是固定的，中间任何一个数变了后面全变：

```
① 应发工资（税前，= 劳动合同月工资）
    − ② 个人承担的社保 + 公积金
    ─────────────────────────────
    = 应纳税所得额基数
    − 5000/月 减除费用 − 专项附加扣除
    ─────────────────────────────
    = ③ 累计预扣预缴应纳税所得额  →  ④ 个税
① − ② − ④ = ⑤ 实发（打到个人卡的数）
```

**个人承担部分（北京，个人侧比例长期稳定）**：

| 项 | 个人比例 |
|---|---|
| 基本养老 | 8% |
| 基本医疗 | 2% + 大额互助（固定小额/月） |
| 失业 | 0.5% |
| 工伤 / 生育 | 个人不缴 |
| 住房公积金 | 与单位同比例（5%–12%，一人公司通常取下限 5%，理由见 `housing-fund.md`） |

**个税用累计预扣法**（不是按月单独算），预扣率表：

| 累计应纳税所得额 | 预扣率 | 速算扣除数 |
|---|---|---|
| ≤ 36,000 | 3% | 0 |
| 36,000 – 144,000 | 10% | 2,520 |
| 144,000 – 300,000 | 20% | 16,920 |
| 300,000 – 420,000 | 25% | 31,920 |
| 420,000 – 660,000 | 30% | 52,920 |
| 660,000 – 960,000 | 35% | 85,920 |
| > 960,000 | 45% | 181,920 |

`本月应扣 = (累计应纳税所得额 × 预扣率 − 速算扣除数) − 累计已预扣`

⇒ 小微一人公司常年落在 3% 档，且前几个月因累计减除费用大于累计收入，**个税经常是 0**。
个税 0 **不等于不用申报**（见 `tax-withholding.md` 零申报）。

## 2. 归属月份：三条链的口径不一样（最容易错的一条）

| 链 | 归属规则 |
|---|---|
| **个税** | 按**钱实际打出去的那个月**归属，与工资"所属月份"无关 |
| 社保 | 按**参保月**，与发薪日无关 |
| 公积金 | 按**缴存月**（托收日），与发薪日无关 |

⚠️ 后果：1 月发放 12 月的工资，这笔是**1 月所得**，在 **2 月 15 日前**申报，
并占用 1 月的 5000 减除费用；12 月则是零申报月。
跨年时如果"12 月工资 1 月发"，会导致**当年只有 11 个月有收入、次年有 13 个月工资落在 12 个月里**，
个人年度汇算时数字看着对不上 —— 这是正常的，不要回去改申报。

## 3. 发薪日怎么定

定在**次月 5–10 日**之间最省事：

- 早于个税申报截止（次月 15 日）⇒ 先发薪、后申报，申报时数字已确定，不用估；
- 晚于社保征期起点（次月 10 日起在电子税务局申报）容易撞，**建议 ≤ 10 日**；
- 公积金托收日自选（≤28 稳妥），与发薪日不必对齐，但**同月对公户要同时扛住实发工资 + 社保 + 公积金三笔**。

⚠️ 发薪日一旦写进劳动合同就别随意改。改了要同步劳动合同，否则形式上是欠薪。

## 4. 对公户实际打款

**人数是个位数时不要办银行「代发工资」协议**，直接对公网银逐笔转账即可，理由：
代发协议要签约、要预维护收款名单、部分银行还有笔数门槛，收益是省几次点击，不值。

打款时：

- 收款人 = 员工本人，收**个人卡**（不能打到别人卡、不能走个人微信/支付宝转账）；
- **摘要 / 用途必须写「工资」**（后续被问到时，这是资金性质的第一层证据）；
- 金额 = ⑤ 实发（不是应发）；
- **回单必须下载留存**，一人一笔一张。

⚠️ **判据只有一条：对公户有没有真把钱打到个人卡。** 现金发薪、股东垫付、
"先转到法人个人卡再分给员工" 都不成立。

## 5. 这个数在三个平台分别填哪

| 平台 | 字段 | 填什么 | 常见错填 |
|---|---|---|---|
| 扣缴端（个税） | 正常工资薪金 → **本期收入** | **① 应发工资**（税前） | 填成 ⑤ 实发 ⇒ 与另填的三险扣除**重复扣除**、收入少报 |
| 扣缴端（个税） | 基本养老 / 医疗 / 失业 | ② 的**个人部分**，以社保实际扣缴额为准 | 填成单位部分或合计 |
| 电子税务局 | 社保**缴费工资** | ① 应发工资 | 填成实发 |
| 公积金单位系统 | 缴存基数 | ① 应发工资 | 与社保基数不一致 |

**三数必须对齐（金税四期比对）**：劳动合同月工资 = 社保缴费基数 = 个税「本期收入」，
公积金基数也取同一个数。时间轴同样要对齐：劳动合同起始日 = 社保参保起始月 = 扣缴端任职受雇日期。

## 6. 每月留痕清单

一笔发薪产生 4 份材料，缺一份就有一环说不清：

1. **工资表**（应发 / 个人社保 / 个人公积金 / 个税 / 实发 五列，本人签字或电子确认）
2. **银行回单**（摘要含"工资"）
3. **个税申报成功截图 / 反馈**（`tax-withholding.md` 里的成功标志）
4. **社保、公积金当月缴款凭证**

按 `~/公司相关事务/发薪/YYYY-MM/` 归档。

## 7. 坑

| 现象 | 根因 / 处理 |
|---|---|
| 个税算出来 0，怀疑填错了 | 累计减除费用 > 累计收入，正常。仍要走完申报拿到"申报成功" |
| 年度汇算显示收入与工资表差一个月 | 个税按实际发放月归属（§2），不是错误 |
| 只计提未发放，年底想税前扣除 | 不行，汇算要调增。想扣就在**汇算前实际发放** |
| 社保基数与工资不一致被系统提示 | 三数没对齐（§5）。基数有当年度上下限，工资低于下限时按下限缴，此时**基数 ≠ 工资是允许的**，但要知道自己为什么不一致 |
| 员工是法定代表人本人，怀疑不能发工资 | 可以，与普通雇员同一套流程，同样要参保、要实际打款 |
