# 社保 + 医保：增员（e窗通员工登记）· 单位登记与查询（人社）· 医保核对（医保公共服务平台）

三个平台分工：

| 平台 | 干什么 |
|---|---|
| **e窗通** `ect.scjgj.beijing.gov.cn`（法人服务 → 员工登记） | **职工增减员的主通道，五险（+公积金）整包** |
| 北京社会保险网上服务平台 `https://fuwu.rsj.beijing.gov.cn/zhrs/yltc/yltc-home`（点「法人办事」） | 用人单位信息登记（户没开时补登）+ 在职/参保查询 |
| 北京医保公共服务平台 `https://ybfw.ybj.beijing.gov.cn/`（单位入口 `#/unitLogin`） | 医保参保关系核对、单位信息补录、月报补缴查询 |

人社权威操作手册：`https://rsj.beijing.gov.cn/yltc/czsmx/`（`ptzn_yhx` 单位登记 / `ptzn_zggl` 在职职工 / `ptzn_jf` 缴费）

## 0. 前置认知

- **同城换工作只需增员，不需要「转移接续」**。转移接续是跨省/跨统筹区才用的。
- **增员主通道是 e窗通「员工登记」**（京社保发〔2021〕6 号：2021-10-15 起企业员工增减员渠道统一为
  e窗通「法人服务 → 员工登记」，五险一金整包、网上即时生效、无需纸质材料）。它的员工表单里
  **没有险种选择器 = 五险整包登记** —— 这正是它跟人社平台（只有养老/失业/工伤三项且置灰）的本质差别。
  **只在人社平台做增员，结果就是只挂上三险。**
- **增员是社保 + 就业 + 劳动用工备案合并办理**，要填劳动合同起止日期 ⇒ 得先有劳动合同。
- ⛔ **不要假设「增员后医保自动同步」。** 官方公告有「社保增减员成功后会同步至医疗部门」的说法，
  但实测人社侧增员完成三周多后，税务与医保侧仍无任何医保参保关系。
  医保参保关系必须到医保公共服务平台**单独核对**（见 §5）；没有就走 §1 的 e窗通通道补
  （它的业务详情页有独立的「医保登记信息」反馈栏）。
- **社保户不一定随工商设立自动开**。人社平台查无此单位时，先做「用人单位信息登记」（§2）。
- **超过法定退休年龄的人不能参加企业职工社保**（男 60 / 女 55、50）⇒ 超龄的股东或负责人不出现在参保人名单里，
  这不是漏办。
- 缴费基数有上下限（按年度通告，历年偏晚发布）。**申报工资低于当年度下限时系统不报错、
  静默按下限核定**；年度切换后旧下限值直接作废。所以「开多少工资」实质是「基数报多少」。
  当年度数值查官方通告，记进私有档案。
- **三数必须对齐**（金税四期比对）：劳动合同月工资 = 社保缴费基数 = 个税申报工资薪金。
- 按下限报的代价很小：缴费年限不受基数影响、医保报销比例不看基数（只影响个人账户划入额）。

## 1. 职工增员：e窗通「员工登记」（主通道，五险整包）

入口：`ect.scjgj.beijing.gov.cn` → 法人服务（北京统一身份认证 yzt 扫码，**登录态隔夜失效**）
→ **员工登记** → 先强制走「指定经办人」（填被委托人姓名/电话/证件/授权期限 + 同意项，代理机构=否）
→ 确认框「开启一笔公积金社保增员业务」→ iframe「聘用员工」→「添加新员工」。

确认框原文：「请确认该员工已从原单位离职并办理减员业务，否则此次增员申请会被退回。
参保登记完成后，**无需再办理就业登记**。」

### 两张表都要填

「添加新员工」保存后弹「该人员需要进行参保登记的人员，请点击列表中参保信息进行完善」
⇒ **必须再点列表里的「参保信息」填第二张表**，否则列表状态一直是「未保存」、提交不了。
第二张表保存成功的弹窗原文：「该职工的就业登记与社会保险参保登记已合并办理完成。」

第一张表必填（★）：职工姓名、证件类型、证件号码、手机号码、申报月均工资收入、
**证件有效期起**、户籍登记地址。选填：性别、证件有效期止（长期身份证可不填）、
公积金个人缴存比例（5%~12%）。

⚠️ **「户籍登记地址」是 3 个控件**：省 + 地区两个只读级联 + 1 个详细地址文本框；
省/地区由证件号码前 4 位**自动带出**，不用也不能手填；级联只到「地区」级
⇒ **区/乡/村全写进详细地址**。

### 制卡照片（新参保人员必传）

一寸 / 正面 / 免冠 / 彩色 / **白底** / 服装与背景反差大，jpg，**恰好 358×441 像素，9KB～20KB**。
⚠️ **上传是异步的，且会挂全屏 loading 遮罩**，期间任何真实点击都被拦（自动化会一直重试到超时）。
上传后轮询等「上传成功」提示或预览图出现再继续；抢着点会拿到「与服务器连接失败」。

### 结果验证：详情页四栏各自独立反馈

提交后「我的业务 → 员工登记 → 详情」分四栏：**社保增员信息 / 公积金增员信息 /
个人信息变更 / 医保登记信息**，各自独立回传，提交当时都是「未反馈」，**需隔日回查**。

- 公积金栏报「个人存在缴存账户，开户失败！」= **撞库**：先查**自己**在其他通道
  （公积金单位网厅）的办理记录 —— 多半是此前已开过户，**不要点「重新办理」**，
  也别直接推给前雇主。教训：看到这个报错第一反应是查自己的办理记录。
- **终判不靠这四栏**：以税务侧「职工参保信息管理」五险全列（见 `etax.md` §3）
  + 医保平台参保名单（§5）为准。

### 自动化坑（e窗通）

- 「员工登记」的可点元素是**外层 `<li>` 卡片**（cursor:pointer），不是文字 SPAN；
  页面刚载入有全屏遮罩，先轮询等它消失再点。
- **第一步的按钮会留在 DOM 里遮挡第二步同名按钮** ⇒ 必须遍历 `button:visible` 按文本匹配。
- Element-UI 单选：真 `input[type=radio]` 被 `span.el-radio__inner` 拦截 ⇒ 点外层 `label.el-radio`。
- 下拉面板**挂到 body 上、不在 `.el-select` 里**，且关闭后仍留在 DOM ⇒ 按容器取选项会读到
  多个面板的并集。可靠姿势：真实鼠标点击打开面板，再在**可见** `.el-select-dropdown` 里
  按 innerText 精确匹配 `li.el-select-dropdown__item`，打标后真实点击。
- 报「未获取到当前登录用户信息，请重新登录」时表单值全在、但**一个字都没写库**。
  **别在旧标签页折腾** —— 另开标签走 法人服务 → 我的业务 → 那条「未提交」的员工登记点「继续」，
  业务和已添加的员工都在，只有第二张表的下拉项要重填。
  从「办理事项」再点一次「员工登记」会被拦：「该企业存在员工增减员管理在办业务」。

## 2. 判断社保户到底开没开（人社平台，唯一可靠方法）

**不要用「页面能不能打开」判断。** 调接口：

```
POST /zhrs/api4/ggfw-server-yltc/unitSearch/queryUnitInfo
Header: Access-Token: <sessionStorage.token1>
Body:   {"starFlag":"1","socialCreditCode":"<统一社会信用代码>"}
```

- 返回 `map.data: []` ⇒ **查无此单位，户没开**。前端会写 `sessionStorage.unitInfo={hasInfo:false}` 并弹「请先进行单位信息登记」。
- 开好之后返回 `unitId`、经办机构代码、以及 `unitInsuranceDTOList` 三条险种记录
  （**110 养老 / 210 失业 / 410 工伤**），每条带 `insuredStatus=1`、`insuredDate`、`startDate=YYYYMM`。

**户没开时的典型误诊**：增员表单里「员工类型 / 用工形式 / 员工岗位」三个下拉点了不生效。
这不是页面 bug，是 `formatIns()` 读 `unitInfo.unitInsuranceDTOList` 抛
`TypeError: Cannot read properties of undefined` —— 根因就是单位没登记。

## 3. 用人单位信息登记（人社平台，户没开时补登）

入口：`/zhrs/yltc/company/information-registration/index` →【开始申报】→ `/register`
页面自述适用场景：「新的企业单位成立后**在社保系统无法同步开户**的」。

5 步：共享信息+关键信息 → 其他信息 → 参保信息 → 附件 → 提交。

**第 1 步**（自动带出且锁定：统一社会信用代码 / 单位名称 / 单位类型 / 成立日期 / 登记注册地 /
执照种类 / 经营范围 / 法定代表人信息）需手填：

| 字段 | 填法 |
|---|---|
| 登记注册地街道 | 按执照地址所属街道/镇 |
| 执照号码 | 同统一社会信用代码 |
| 发照日期 | 对执照原件 |
| 有效期限 | 勾「长期」→ 自动写 `9999-11-11` |
| 经济类型 | 如「私营有限责任（公司）」`AAB020=173` |
| 隶属关系 | 如「区」`AAB021=51` |
| 所属行业 | 按主营 |
| 是否签订集体合同 | 否 |
| 国家/地区 | 中国 `CHN` |
| 发证机构 | 执照上的市场监督管理局全称 |

选完经济类型后「批准成立部门 / 批准文号 / 批准成立日期 / 28号文分类划转标识」整块自动隐藏，不用填。

**第 2 步**：经办联系人 + 经办联系人手机 + **手机验证码（短信，必填）** + 单位联系电话。
短信接口 `POST /ggfw-server-yltc/msc/sendShortMessage2`，60s 倒计时，验证码约 5 分钟有效。
险种类型：单位类型=企业 + 经济类型=私营 时，只剩 **基本养老 / 失业 / 工伤 三项且全勾且 disabled**
（「机关事业单位养老保险」「职业年金」自动消失，**这个平台天生没有医疗** —— 又一个
「医保要单独核」的佐证）。

**附件**：要件列表只有「其他材料 / 非必要」⇒ **不强制上传任何材料**。

**提交**后端依次调 `CommonBusiness/checkLegalPerson` → `msc/chenkMessageCode` →
`attachment/materialUploadVerification` → `exportFile/exportShareInfoFormAndUpload` →
`attachment/uploadProcessSnapshot`，页面弹「您提交的用人单位信息登记申请已提交，请您退出系统后重新登录查看。」

### ⚠️ 两个必知

1. **登记是即时生效的，不是等审核。** 重新登录后 `queryUnitInfo` 立刻返回完整数据。
   别让用户干等审核。
2. **提交成功会连带杀掉统一身份认证（yzt）SSO 会话**，不只是 yltc 的 token。
   之后 `queryUnitInfo` 直接 401 `Full authentication is required`，SSO 深链也被打回法人登录页。
   **要查结果必须让用户重新扫电子营业执照登录 —— 别把这个 401 误判成「提交失败」。**

## 4. 职工增员（人社平台，仅三险，2021 年起非主通道）

⚠️ **此通道只挂养老/失业/工伤三险，2021-10-15 起增减员应优先走 §1 e窗通。**
此节保留供存量业务与查询参考。

入口：`/company/information-third-new/index?resource=1` →【零星新增】→ `/add`

**省一半字段的填法**：只填 证件类型=居民身份证（户口簿）+ 证件号码 + 姓名，
然后点 **【获取共享信息】** —— 性别 / 出生日期 / 民族 / 手机号码 / **户口性质** / 国家地区 全部自动带出。
⚠️ **户口性质别自己猜**（本地城镇 / 外地非农业户口（外地城镇）等，`AAC009`），交给共享信息判定。

手填 7 项：

| 字段 | 值示例 | 字典码 |
|---|---|---|
| 员工类型 | 本单位员工 | `BAB114=1` |
| 用工形式 | 订立固定期限劳动合同 | `AAC013=41` |
| 劳动合同起始日期 | 与合同一致 | |
| 劳动合同终止日期 | 与合同一致 | |
| **签订劳动合同日期** | 与纸质合同落款一致 | |
| 员工岗位 | 管理、专业技术岗 | `BAB115=1` |
| 是否已签订电子劳动合同 | 否 | |
| 个人身份 | 企业管理人员 | `AAC012=21` |

险种三项自动全勾且 disabled；附件要件列表「暂无数据」⇒ 一个都不用传。

**表单里没有缴费基数字段，也不需要上传劳动合同。** 页面弹窗原文：「2024年1月以后办理参保登记手续的人员，
用人单位自办理参保登记成功的**次月10日起**应及时向**税务部门**申报缴费工资」
⇒ **基数是在电子税务局报，不在人社报。**

**提交**：【提交】→ 弹**自定义**确认框「本次税务开始缴费时间为 YYYYMM」（按钮：返回修改 / 确定提交）
→ 跳 `/yltc/success?now=0&aaz002=<流水号>`，文案「您的申请已受理成功！…属于即时办结」。

### ⚠️ 验证规则

- 这个确认框**不是** `.el-message-box`，用 `.el-message-box__wrapper` 选择器**抓不到**。
- 点【确定提交】那一步**监听不到 `/zhrs/api4` 请求**，别据此判定「没提交成功」。
- **唯一可靠验证 = 打开 `/company/information-third-new/tabList` 的「在职」页签，看这个人在不在**，
  核对姓名/证件号/岗位/险种/合同起止。

### 其他

- 零星新增**支持勾选补缴近 3 月**；批量新增不支持补缴。
  同城换工作时上家可能已缴到某月，**重复月份不要补缴**（先查个人权益记录确认缴至哪月；
  重复缴费要事后办退费，麻烦）。
- 增员后员工另走「社会保障卡集成服务一件事」提交制卡照片（规格见 §1）。

## 5. 医保公共服务平台（ybfw）单位侧

平台 `https://ybfw.ybj.beijing.gov.cn/`。
⚠️ `fw.ybj.beijing.gov.cn` 301 跳信息门户、`/hallEnt/` 404，都不是入口。
单位入口 `#/unitLogin`（门户首页主体有可见的「单位登录」按钮；导航栏「登录」下拉是
el-dropdown 隐藏项 rect 0×0 点不动）；登录后大厅在 `/hallUnit/#/Home`。
已登录态访问 `#/unitLogin` 会被重定向到 `#/index`，要先「退出」。

### 两种账号别混

| 账号 | 登录方式 | 能干什么 |
|---|---|---|
| 单位管理账号 | 电子营业执照扫码 | 只能维护单位信息 + 管理经办人 |
| 单位经办人账号 | 经办人手机号 + 密码 | 办业务（权限要管理账号先授予） |

新单位首次进来要做**单位信息补录**（信用代码 / 地址 / 法人 / 联系电话）。

⚠️ 经办人首页显示「常用服务：暂无权限，请联系单位管理员！」是**正常的** ——
管理账号「权限管理」里只有 医疗机构业务办理 / 招采企业业务办理 / 直接结算业务办理 /
医疗服务价格业务办理 四个功能角色，**全是给医院药店招采企业的，用人单位没有可勾的角色**。
别再去权限管理里找，这不是配置问题。

### 核对医保参保关系

「参保单位正常参保人员基本信息查询」**必须选证件类型下拉（居民身份证（户口簿））才出数据**。
能看到参保身份（如外埠城镇职工）、人员编号、定点医院。
新参保单位同时核对「单位网上经办事项办件进度」和缴费明细 —— 都空不代表没参上，以人员名单为准。

### 月报补缴查询是异步的

「参保单位月报补缴」提交后**等约 10 分钟再查结果**。
返回「没有查到该单位有需要补缴的信息」= 医保系统不认为你欠费，**不等于已出账** ——
新参保单位首月应收常随月底批处理一起出（首月并入次月批次）。
到征期税务侧仍无医保账单，打参保区医保事务管理中心电话问应收核定（电话记私有档案）。

### 自动化坑（ybfw）

- ⭐ **图形验证码**：截图存文件后**用多模态模型直接读图识别**（原图 69×28 就能看清），
  几秒内填入提交；**别走本地 vision 脚本**（单次 >120s，必触发「验证码超时」）。
  定位：按与验证码 input 同一行（y 中心差 <30px、x≥input.x-5、宽 40~250）筛 `img,canvas`，
  别按尺寸或 DOM 邻近（会抓到政府徽标 / 站点 logo / input 图标）。
- **登录成功不立即跳转**：点登录后可能仍停在 unitLogin 十几秒才跳大厅，别当失败重试。
- 「选择登录单位」dialog：行的 radio 是 `label.el-radio.mySelect` 且 Playwright 判定
  not visible ⇒ 用 JS `label.click()`，再 JS 点「确认登录」。
- 顶部菜单 `.el-submenu__title` 有的要 click 展开（hover 不灵）；菜单项点
  `li[role=menuitem]` 里可见的那个；页面都是 hash 路由。
- 查询页日期框直接 `fill('YYYY-MM')` + Enter。
- 用 `locator.fill("")` 再 `fill(val)` 设值，**不要 `evaluate` 直接赋 value**
  （会与 Vue 受控值叠加，账号变长、密码多字符）；提交前回读 `input_value()` 断言长度。
- 报错弹窗读 `.el-message-box`（`.el-message-box__message` 抓不到）；
  「账号或密码错误」**5 次锁 10 分钟**，计数约 10 分钟后自行重置。
- 统一认证 `code=` 一次性且有时限，表单里试探校验规则会把它耗尽
  ⇒ 补录类流程写成一次跑完的非交互脚本，别边试边填。

## 6. 单位侧查不到别家缴费记录

单位侧唯一查询路由 `/company/join-query/index` 只含本单位人员。
别的单位缴到几月属个人数据，只能走 `portal.bjt.beijing.gov.cn` 查「社会保险个人权益记录」
（京通 APP 扫码 / 账号 / 支付宝 / 微信 / 电子社保卡登录）。

## 7. 劳动合同

- 模板：北京市人社局官方《固定期限劳动合同》.doc（便民下载栏目 `/fuwu/bmxj/gz/` 一类路径；
  ⚠️ 站内搜到的《劳动合同书（示范文本）》可能是**建筑施工企业专用版**，转文本看副标题再下）。
- **签章的真卡点是公章，不是法人的手**：模板《使用说明》原文「甲方应加盖公章；法定代表人或主要负责人
  应本人签字**或盖章**」，落款栏印「法定代表人**或委托代理人**（签字或盖章）」。
  三条路：① 公章+法人名章 ② 法人出一次性授权委托书（工商/税务/社保可复用），他人以委托代理人签 ③ 电子签。
- **电子劳动合同合法**：北京市人社局《关于推进电子劳动合同相关工作的实施意见》(2020-10-27)
  `https://rsj.beijing.gov.cn/xxgk/2024zcwj/202406/t20240617_3717115.html`
  ——须**可靠电子签名** + 通过签署系统管理 + 第三方持《电子认证服务许可证》；
  「办理人社政务服务事项时不得以电子形式不属于书面合同为由否认其法律效力」；**社保稽核/劳动监察中可作证据**。
- ⚠️ 纸质合同的「签订日期」必须与增员备案里填的一致。

## 8. 站内搜政策原文的可行路径

WebSearch 对这类查询返空、Bing 中文结果被污染。可行：
`https://rsj.beijing.gov.cn/so/s?tab=all&siteCode=1100000062&qt=<urlencode(关键词)>`
—— 但结果是 JS 渲染，curl 拿不到 ⇒ **用 Playwright over CDP 打开，等 5~6 秒后读
`document.querySelectorAll('a')` 的 innerText+href**。政策文件正文页可以直接 curl。

⚠️ **引用政府文件先核适用期间**（本领域踩过）：标题或首段带「期间 / 过渡 / 暂行 / 试点 /
停机切换」字样的，先确认是否现行有效 —— 曾把系统停机切换期间的临时通知当现行规定，
误判「医保首次参保必须去窗口」，白计划一趟窗口。
