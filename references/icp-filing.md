# ICP 备案

具体域名 / 备案号 / 接入商账号进私有档案，本文只留通用规则与踩过的坑。

## 1. 备案三条件（缺一不可）

1. **域名后缀在工信部批复名单内**（例：`.cc` 自 2020-07 获批，可备案；接入商按可备案受理）
2. **注册商有境内资质**（国内注册商如新网/万网/腾讯云都可；国外注册商需先转入）
3. **域名实名信息与备案主体一致** —— 企业备案要求域名持有者姓名/证件与「主体名称**或法定代表人**」匹配。
   不一致要先做过户 / 实名变更，再进备案。

⚠️ **一人公司高频坑**：域名常常是当初**用个人名义**随手买的（甚至挂在一个不常用的个人账号下）。
企业备案时实名落在某个自然人、而此人**既不是法定代表人也不是公司** ⇒ 必须先过户，过户本身还要等。
**买域名的那一刻就落到公司或法定代表人名下**，比事后过户便宜得多。

⚠️ **注册商 ≠ DNS 权威，别找错后台。** 从云厂商买域名时，云厂商往往只是**代理注册机构**，
whois 里显示的是它背后的那家注册商，而 **DNS 权威可能在云厂商这边**。
所以"改解析找不到入口"通常是找错了地方：先 `dig NS <域名>` 看权威 NS 指向谁，按 NS 去那家后台改，
别按 whois 的注册商找。

## 2. 前置条件

- **必须先买服务器**：包年包月 ≥3 个月的境内云 ECS，且开放公网 80/443。
  **按量付费的实例不能用来备案** —— 选型与计费口径见 `cloud-server.md`。
- **要挂备案指向占位页**（nginx 起来、`http://<公网IP>/` 返回 200）。
- **备案期间该域名不能对外提供 web 服务** ⇒ **A 记录先不要配**，
  避免管局查到「未备案对外提供服务」。备案通过后再配 DNS。
- 备案在**服务器所在云厂商的备案控制台**做，不在域名注册商那边。

## 3. 流程与时长

主体信息（营业执照 + 法定代表人身份证 + 主体负责人）→ 域名 → 绑定 ECS → 提交接入商初审
→ **工信部 24h 短信核验** →（部分厂商还要 App 人脸核验）→ 管局审核。

- 管局审核实测约 **7 个工作日**（官方口径 10–20 工作日）
- 中途可能被要求**重新做一次短信核验**，不代表被拒
- 通过后拿到备案号形如 `京ICP备XXXXXXXXXX号-1`

## 4. 备案通过后的三件收尾（容易忘）

1. **配 A 记录**（主域名 / `www` / `api` 等子域指向 ECS）
2. **certbot 上 HTTPS**（很多站只开了 80 就以为完事）
3. **网站页脚展示备案号**（工信部要求，且要能点开链到工信部查询页）

⚠️ **刚加的 DNS 记录立刻签证书会撞 NXDOMAIN。** Let's Encrypt 会从多个校验节点做**二次校验**，
其中一些还缓存着**记录创建之前**的否定应答（negative caching），于是报域名不存在。
判据不是"DNS 没配对"——用 `dig` 查权威已经能返回记录了。
解法：查该域的 **SOA `minimum`**（否定缓存 TTL，常见 300s），**等过这个 TTL 再跑 certbot**。

## 5. 子域名沿用主域备案 —— 新业务上公网的零等待路径

**子域名不需要单独备案**，直接沿用主域名那次备案。
⇒ 新业务要上公网，走 `xxx.<主域>` 是**零等待**的：配 A 记录 + certbot + 页脚备案号，当天就能上线。

只有启用**独立的品牌域名**才要走「同主体新增网站备案」，再等管局那 7 个工作日。

⇒ **对一人公司的实际含义**：不要为每条新业务线都买一个新域名再各备一次案。
先用子域把业务跑起来，等这条线确定要独立品牌了再买域名走新增备案。

## 6. 坑

### 主体唯一性：一个账号一个主体，一个主体一个账号

这条规则有**两个方向**，两边都会咬人：

**方向一：主体已在别的账号里备过 ⇒ 你这个账号备不了。**
再次备案时报 403 `Core.Business.OperateForbidden`
「已查到对应的备案主体，但该主体已在账号 `X**X` 中完成备案」——
**这不是资料问题，重试一百次也是 403**。两条解法：

- **能登原账号** ⇒ 在原账号内做「新增网站备案」，或「授权其他账号备案」发服务码过来（线上转移即时生效）
- **登不了原账号** ⇒ 走**线下转移**（联系接入商售后，约 1–3 工作日）。
  官方口径「申请人无需与原备案人一致」⇒ **不需要找回老账号，也不需要原备案负责人配合**。
  企业所需材料：营业执照扫描件 + **申请人手持营业执照原件半身照** + 申请人身份证正反面 +
  **授权委托书**（用接入商模板，签字日期距提交 ≤30 天）+ 转入账号 UID。
  ⚠️ 转移是把该主体下**所有**备案信息整体转过来，**无法只转一个域名** ⇒
  转来后先注销不用的老网站，再「新增网站备案」加新域名。
- 忘记备案账号：可用**备案域名**去接入商「找回登录名」；查不到说明备案不在这家接入商，
  需找属地管局或其他接入商。

**方向二：一个云账号只能装一个备案主体。** 同一主体下可以备多个网站/App，
但**要给第二个主体备案，必须另开一个云账号**。
⇒ 顺手用自己公司的账号帮别的主体（客户、朋友的公司）备案，会把这个账号**永久占用**掉。
接私活或代办前先想清楚这一点。

⚠️ 并且：**历史备案锁定主体后，无法通过「变更备案」去改证件号**（MIIT 规则）。
主体选错的代价很高，**首次备案前把主体确定死**。

- 云厂商备案**不校验云账号自身的实名信息**是否与备案主体一致（官方 FAQ 明确），
  所以"账号实名是谁"不拦备案；拦你的只有上面那条主体唯一性。

### 备案账号里有没有"进行中订单"决定能不能转入

线下/线上转移的前提是转入账号**没有进行中的备案订单、也没有其他主体的备案信息**。
判据用接口而不是页面文案：`my/orderInfo.json` 与 `my/completedOrderInfo.json` 都返回
`totalCount 0` / 空数组 ⇒ 满足。

### 域名实名状态：看接口，不看列表页标签

阿里云实测：域名列表页标「未实名」、详情页写「实名认证成功」，两个 UI 自相矛盾。
权威口径是接口：

```
https://dc.console.aliyun.com/domainApi/queryDomainList.json?currentPage=1&pageSize=20&pureType=true
```

- `domainAuditStatus: "SUCCEED"` = 实名已通过
- `ccompany` = 持有者名称（用来比对是否与备案主办单位一致）
- `registrantType: "2"` = 企业
- 另有 `chgholderStatus` / `domainStatus` / `expirationDate` / `dnsList`

⚠️ 域名详情页 SPA 正文经常 7s 内渲染不出来，`document.body.innerText` 只剩导航壳，**别据此下结论**。

### 查某域名有没有备案

阿里云：`tools/baStatusContent/get.json?type=domain`（返回「未备案」/已备案）。

### 只能人工做的部分

营业执照扫描件、法定代表人身份证正反面、主体负责人短信核验与人脸核验 —— 都要人。
查别人已有备案的详情也需要**原备案负责人姓名+手机号**做短信验证，自动化读不到。

### 查备案状态别用这两条路

- 接入商的「查域名是否备案」接口**在未登录态下没有判别力**（对明显已备案的域名也返回空）
- 工信部公共查询站的 auth 接口能拿到 token，但真正的查询接口**被 WAF 打 403**，
  浏览器同源 `fetch` 也一样失败

⇒ 判"到底备没备"最可靠的还是：登录接入商账号看订单/备案列表，或直接 `dig` + 访问看服务是否在跑。

## 7. 和小程序备案的关系

**两件事，各办一次。** 本文讲的是**网站** ICP 备案（云厂商侧）；
小程序备案在**平台侧**（微信/支付宝后台）办，不依赖服务器和域名 —— 见 `miniapp-filing.md`。

小程序的**后端 API 域名**属于"网站"，要按本文流程备案。
